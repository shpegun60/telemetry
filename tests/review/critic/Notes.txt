Critic trial log - telemetry + resource libraries as a first-time adopter (2026-09-25)
==================================================================================

Scope: everything here was built by hand with plain compiler invocations (no qmake,
no repository runners). Build outputs are in build/review-critic/ only.

                            values and command schema; optional resource dump
CriticResources.cpp         C++20: schema.bin/commands.bin/values.bin + one protocol READ
CriticFirmware*.cpp         Cortex-M7 image variants for arm-none-eabi-size

Time to first working program
-----------------------------
Reading root README + lib/telemetry/README.md (1572 lines) + resource READMEs: the bulk of
the effort (a human reader: 1-2 h; the library README alone is ~33k tokens).
Host fields/commands/JSON consumer: compiled and ran on the FIRST attempt (~2 min of writing).
Resource consumer: FIRST attempt, but only after opening Types.hpp to learn that
resource::Output is std::span<std::byte> (not stated in the README).
Python decoder of schema.bin/values.bin from the README spec alone: first run, ~10 min.

Friction log
------------
F1  No CMake/Make/Zephyr/PlatformIO integration; the only build glue is qmake .pri files.
    The non-qmake recipe is two sentences (lib/telemetry/README.md lines 17-22).
F2  Two include conventions: telemetry expects -Ilib/telemetry and "Telemetry.h"; resource
    expects -Ilib and <resource/...>, <telemetry/...>. A mixed consumer needs both paths.
F3  Resource library requires C++20 (span, concepts, constinit) while telemetry is C++17:
    a C++17 firmware cannot use the binary files at all.
F4  Resource README shows files.read(0, 0, output) but never what Output is, nor a read loop.
F5  lib/telemetry/README.md is internally inconsistent: "telemetryAbiVersion is 7" (l.690),
    "ABI 7" (l.1273, 1286, 1423) vs ABI 8 (l.1553, code); "Catalog 16" (l.1471) vs 12 (l.1423,
    measured). archive/id_ranges/README.md points to a moved path.
F6  README reads as a verification log: cycle counts, byte-identical object hashes, board
    windows, migration notes for ABI 5/6/7 - no task-oriented "getting started" or API reference.
F7  Values JSON carries no schema fingerprint (schema JSON has a 32-bit one; binary has a
    different 64-bit one), so a JSON client cannot detect a stale schema from a values poll.
F8  F32 values print with 9 significant digits: 230.1f -> 230.100006, 33.3333f -> 33.3333321.
F9  No wire path for field writes or command execution: the three resource files are read-only
    and commands.bin "is not a new execution protocol". The adopter designs write/execute framing.
F10 No host client for the packet protocol and no non-JS decoder (web/telemetryBinary.js only,
    package.json is private, no npm package, no TypeScript types).
F11 Duplicate field and group names compile silently; values JSON then has duplicate keys:
    {"protection":[260,280],"protection":[280,260]}. The optional names_unique() check fails
    with a bare "static assertion failed" that does not name the duplicate.
F12 Reordering rows silently re-targets cached IDs: a stale write of the over-voltage trip level
    landed in the under-voltage threshold and returned Applied (CriticHazards.cpp). There is no
    write-with-expected-fingerprint API.
F13 No strings/arrays/blobs/structs: a 63-element float array needs 63 fields, 6048 B of
    descriptors (63 x 96) and a 6114 B schema.
F14 Cache-line alignment cannot be disabled (#error "at least 32"); Cortex-M0/M3/M4 without a
    data cache still get 96-byte, 32-aligned Fields (natural layout would be ~80 B).
F15 Describing two command parameters (arg<0>, arg<1>) links FieldType::withLimits (~7.8 KB at
    -Os) even if no command schema is ever serialized.

Portability
-----------
Consumer builds warning-free (-Wall -Wextra -Werror -pedantic-errors) with MinGW g++ 13.1,
MSYS2 g++ 15.2, clang++-18 (WSL Ubuntu 24.04) and arm-none-eabi-g++ 14.3.1. The 64-bit schema
fingerprint is identical on Windows and Linux (965579a9e540a38b).
