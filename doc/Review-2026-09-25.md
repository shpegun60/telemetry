## 4. Themes found independently by several reviewers

**Platform-dependent schema types** (numeric core invariant 7, catalogs/JSON
invariant 9, commands invariant 8, resource invariant 7; slots invariant 7 for
the related capacity case). The type Scalar and the schema infer from a C++ type
is chosen by its size and signedness, and those differ between host and
firmware:

- `char`: S8 on x86, U8 on ARM (plain `char` is unsigned on arm-none-eabi).
- `size_t`: U64 on 64-bit hosts, U32 on ARM.
- `long`: S64 on Linux x86-64, S32 on Windows and ARM.
- `wchar_t`: S32 on Linux, U16 on Windows, U32 on ARM.
- An unscoped enum without a fixed underlying type: 32-bit on the host, 1 byte on
  arm-none-eabi (short enums); this covers the test suite's own `Legacy` enum.
  Char-based enums follow `char`.
- Accessor portability: `get<int>()` compiles on hosts but not on arm-none-eabi
  (where `int32_t` is `long`); `get<long long>()` compiles on MinGW and ARM but not
  on Linux x86-64.
- Default owned-slot capacity: Align 16 and 8-byte pointers on x64, Align 8 and
  4-byte pointers on Cortex-M7 (details in 5.5).

Consequence: the same catalog source gives a different schema `"t"`, binary type
code and fingerprint on host and firmware. Use fixed-width types
(`std::intN_t`, `std::uintN_t`, enums with a fixed underlying type).

**Stale counts in `tests/README.md`.** "fourteen suites" at line 50 while
`tests/run_checks.py:12-16` runs 15 since `f17a253` (reported by numeric core,
catalogs/JSON, commands and slots). "38 positive … translation units" at line 121
while the ARM runner compiles 39 (numeric core, catalogs/JSON, slots). Further
stale counts per slice are listed in each section.

**Performance and layout claims older than the code they describe.** Command is
20 bytes on ARM32, not 24 (commands). The H7S DWT command timings predate ten
command-layer commits (commands). A stack-table row reports the wrong function and
hides growth (resource). ARM instruction patterns described in `tests/README.md`
are not enforced by the gates for six probes (numeric core).
`tests/position_tables/compare_schema.py` now fails (catalogs/JSON). The ABI
version is still called 7 in several places (catalogs/JSON).

**Compile-fail cases whose reason is not checked tightly.** One regex for all 26
table cases, and `deleted|no matching` for the lifetime cases (commands);
`tests/resources/run.py` checks only the exit code of `Negative.cpp`, and cases
9–11 fail for a different reason than the one intended (resource); slots cases 27
and 28 fire three assertions and the runner's pattern matches the third (slots).
Commands table case 24 passes for a reason other than its purpose (CM-F3).

**Build modes that no CI job or runner exercises.** GCC with UBSan or
`-fno-delete-null-pointer-checks` (SL-F1); Clang's single `-fno-honor-*` flags
(NC-F1); `-Ofast` and `-ffp-model=fast` (rejected, but untested); `--gc-sections`
with an unreferenced ABI anchor (CJ-F1). Sanitizers run with Clang only.

**Sentinel values that collide with valid data.** A computed fingerprint can be
0, the error value (CJ-F3); a null command name forces that 0 for a whole index
(CM-F3).

**Runtime IDs and positions are narrowed without a check.** `makeId()` (CJ-F2),
`CommandTable::call(size_t, …)` and `uint32_t` `CommandId` (CM-F2), whereas
template positions are range-checked before narrowing.

**Claims that are true but untested.** Runtime `std::abort` for invalid limits
(numeric core), a too-small cache line on x86-64 (numeric core), runtime abort for
invalid command metadata (commands), rejection of more than 65536 entries or
groups (catalogs/JSON), empty-slot `invoke()` behaviour and the non-delegate slot
subset (slots), and several resource paths (resource). Details per slice.

#### NC-F1 — the fast-math guard misses Clang's `-fno-honor-nans` and `-fno-honor-infinities` used alone

- **Severity:** Low (latent). **Confidence:** confirmed by repro.
- **Location:** [`lib/telemetry/detail/TelemetryNumberConversion.h:21-24`](../lib/telemetry/detail/TelemetryNumberConversion.h#L21-L24);
  the branches it loses are at [`:67-71`](../lib/telemetry/detail/TelemetryNumberConversion.h#L67-L71).
- **Defect:** Clang sets `__FINITE_MATH_ONLY__` to 1 only when both flags are
  given. With just one of them the macro stays 0, the `#error` does not fire, and
  the NaN or Inf branch is optimised away.
- **Scenario** (clang-18 at -O1 and -O2):
  - under `-fno-honor-nans`, an F64 NaN converted to F32 is rejected; correct
    behaviour is to keep it as NaN;
  - under `-fno-honor-infinities`, +Inf converted from F64 to F32 is rejected in the
    same way;
  - the NaN rejections for integer targets and for writes still held in this run,
    but once the compiler is allowed to assume no NaN that is no longer guaranteed;
  - `-Wnan-infinity-disabled` stops only the `-fno-honor-infinities` case, and only
    when `-Werror` is on.
- **Repro:** [`tests/review/numeric-core/HonorFlagsProbe.cpp`](../tests/review/numeric-core/HonorFlagsProbe.cpp);
  [`fast_math_matrix.sh`](../tests/review/numeric-core/fast_math_matrix.sh) runs the
  whole flag matrix.
- **Fix idea:** reject these flags explicitly under `__clang__`, or force a precise
  floating mode around the primitives (for example
  `#pragma float_control(precise, on, push)`, verified with this probe), and add
  both flags to the runner.

No other defect was confirmed. Three behaviours looked suspicious but are
deliberate, documented policy:

- double-to-float conversion rejects finite values just above `FLT_MAX` that IEEE
  rounding would bring down to `FLT_MAX`;
- an F64 NaN converted to F32 loses its sign and payload;
- explicit native endpoints are indistinguishable from omitted ones.

#### What a future developer must know

1. **Adding or reordering a Scalar type touches many hand-written switches.** Type
   codes equal the variant index ([`TelemetryScalar.h:42-65`](../lib/telemetry/core/TelemetryScalar.h#L42-L65));
   append only. The eleven types are listed by hand in:
   - [`TelemetryConversion.h:36-74`](../lib/telemetry/core/TelemetryConversion.h#L36-L74);
   - [`TelemetryNumberConversion.h:139-155`](../lib/telemetry/detail/TelemetryNumberConversion.h#L139-L155);
   - the `FieldBounds` union in [`TelemetryBounds.h:29-54`](../lib/telemetry/detail/TelemetryBounds.h#L29-L54);
   - `TelemetryFieldType.h`: `boundsFor_`, `project_`, `nativeBounds_`,
     `nativeDefault_`, `withLimits`, `acceptsConverted_`;
   - [`TelemetryJsonValue.h:25-42`](../lib/telemetry/detail/TelemetryJsonValue.h#L25-L42)
     and [`54-89`](../lib/telemetry/detail/TelemetryJsonValue.h#L54-L89).

   A missed case falls into a `default:` branch and silently returns false or Null;
   it does not fail to compile.
2. **The float-to-integer bounds are shaped on purpose**
   ([`TelemetryNumberConversion.h:87-94`](../lib/telemetry/detail/TelemetryNumberConversion.h#L87-L94)).
   The upper bound is built as `(max/2+1)*2` so that it is exactly 2^N. Casting
   `max()` to float instead rounds up to 2^31, 2^63 or 2^64 and admits undefined
   casts. The signed lower bound uses `> lower-1` only when the source type has
   more digits than the target.
3. **Conversion is not where finiteness is enforced for writes.** Identity
   conversions skip every check, so NaN and Inf pass through. Unrestricted float
   writes are rejected only by `acceptsConverted_` / `acceptsNative_`
   ([`TelemetryFieldType.h:215-245`](../lib/telemetry/field/TelemetryFieldType.h#L215-L245)),
   and any new write path must call them.
4. **`withLimits` converts min, max and default to the declared type before
   comparing them** ([`TelemetryFieldType.h:111-132`](../lib/telemetry/field/TelemetryFieldType.h#L111-L132)).
   Integer limits therefore truncate: a minimum of -1.5 becomes -1. `restricted_`
   means only "bounds differ from native lowest()/max()"
   ([`:83-84`](../lib/telemetry/field/TelemetryFieldType.h#L83-L84)).
5. **`boundsFor_<T>` does not check the type tag**
   ([`TelemetryFieldType.h:39-52`](../lib/telemetry/field/TelemetryFieldType.h#L39-L52)).
   Callers must pass the stored alternative. This is safe today only because an
   explicit `FieldType` is allowed only for Scalar-returning getters
   ([`TelemetryFieldBinding.h:296-359`](../lib/telemetry/detail/TelemetryFieldBinding.h#L296-L359)).
6. **Always spell exact accessor types as `std::intN_t`.** `get/getIf<T>` and
   `NativeType` accept only those. `get<int>()` compiles on hosts but not on
   arm-none-eabi, where `int32_t` is `long`. `get<long long>()` compiles on MinGW
   and ARM but not on Linux x86-64
   ([`PortabilityProbe.cpp`](../tests/review/numeric-core/PortabilityProbe.cpp)).
7. **`Scalar::from` picks the type by size and signedness**, so some C++ types map
   differently on host and firmware: `char` becomes S8 on x86 and U8 on ARM;
   `size_t` becomes U64 on hosts and U32 on ARM; the same applies to `long`,
   `wchar_t` and the underlying type of an unfixed enum. A getter or enum using
   these produces a different schema `"t"` and fingerprint on host and firmware;
   use fixed-width types.
8. **The fast-math guard is a preprocessor check only.** It cannot see
   function-level `optimize` attributes or the Clang flags of NC-F1.
9. **Automatic enum dictionaries depend on magic_enum's scan range** (default
   -128..127). `enum_range` specialisations must be identical in every translation
   unit. Enumerators outside the range drop silently from both the names and the
   bounds. Explicit lists keep their order, which is part of the fingerprint, and
   must have unique codes and names. The default is the smallest code.
10. **Cache-line settings must match in every translation unit and library.**
    x86-64 cannot use 32 (the Setter is 16 bytes there). The Cortex-M default of 32
    gives a 96-byte Field aligned to 32. On MinGW 13.1, stack, heap and vector
    Fields are 64-aligned at -O0, -O2 and -Os
    ([`LocalAlignmentProbe.cpp`](../tests/review/numeric-core/LocalAlignmentProbe.cpp)).

#### What a future developer must know

1. **ID packing.** A packed ID is `(group << 16) | entry`. `makeId` and `catalog()`
   take `uint16_t` and silently wrap. Only `FieldTable::read<Pos>()` checks the full
   width (`positionValue`).
2. **Constructor trick.** The pointer/count constructors of `Catalog` and
   `CatalogIndex` are `template <class = void>` only so that the deleted
   rvalue-array overloads win ([`TelemetryCatalog.h:28-43`](../lib/telemetry/catalog/TelemetryCatalog.h#L28-L43),
   [`TelemetryIndex.h:34-50`](../lib/telemetry/catalog/TelemetryIndex.h#L34-L50)).
   Do not de-template them. Clipping to 65536 protects the ID space, not memory.
3. **Schema output and fingerprint must change together.** Anything added to
   `writeSchemaWithOptions_` must also be hashed in `schemaCrcAbi`
   ([`TelemetryJson.cpp:104-199`](../lib/telemetry/serialization/TelemetryJson.cpp#L104-L199));
   the same holds for commands ([`TelemetryCommandJson.cpp:81-90`](../lib/telemetry/serialization/TelemetryCommandJson.cpp#L81-L90),
   [`124-168`](../lib/telemetry/serialization/TelemetryCommandJson.cpp#L124-L168)).
   The empty-schema CRC `110cc495` is pinned at
   [`TelemetryJsonCheck.cpp:310`](../tests/TelemetryJsonCheck.cpp#L310). Adding a
   `FieldFlag` or changing `jsonSchemaFormatVersion` changes every field fingerprint.
4. **Int64 mode.** `JsonInt64Mode` must not enter any hash; it acts only through
   `JsonWriter::quoteInt64` in `appendScalar`.
5. **Writer invariant.** While `ok_` holds, `offset_ < size_` and
   `buffer_[offset_] == '\0'`. Failure is sticky and `length()` returns 0. Getters
   run only in `writeValuesWithOptions_`, after the preceding comma or prefix has
   fitted; keep that ordering.
6. **Format strings.** `JsonWriter::append` forwards to `snprintf` without compiler
   format checking, so argument types must match `PRIu32`/`%u`/`%lu` exactly. U64
   and S64 must never go through printf (newlib-nano has no `long long`).
7. **ABI version bump.** A new descriptor member needs its size and offset in
   `CurrentAbiTag` ([`TelemetryAbi.h:59-112`](../lib/telemetry/abi/TelemetryAbi.h#L59-L112))
   and a version bump. Then update [`tests/abi/LegacyAbi6Link.cpp:5`](../tests/abi/LegacyAbi6Link.cpp#L5)
   and [`LegacyAbi7.h:4`](../tests/abi/LegacyAbi7.h#L4) (both assert version 8) and
   the `CurrentAbiTag` default arguments in `lib/resource/telemetry/*File.hpp`.
8. **Guard reach.** The guard covers only tagged references that survive linking.
   Translation units that exchange descriptors without such a reference are never
   checked.
9. **Platform-dependent schema types.** `char` is s8 on x86 and u8 on ARM; `long` is
   s32 on Windows/ARM and s64 on Linux x86-64; `wchar_t` is u16, s32 or u32. The
   same definitions give a different `t` and fingerprint on host and firmware. Use
   fixed-width types ([`PlatformTypeProbe.cpp`](../tests/review/catalog-json/PlatformTypeProbe.cpp)).
10. **Command parameter commas.** Comma placement relies on the generated dense
    0..N-1 visitation order ([`TelemetryCommandJson.cpp:105`](../lib/telemetry/serialization/TelemetryCommandJson.cpp#L105):
    `index == 0`).

#### What a future developer must know

1. **Self-referential tables.** Every descriptor in a CommandTable points into the
   table's own `metadata_` tuple ([`TelemetryCommandTable.h:32-43`](../lib/telemetry/command/TelemetryCommandTable.h#L32-L43),
   [`80-86`](../lib/telemetry/command/TelemetryCommandTable.h#L80-L86)). Keep
   `metadata_` declared before `commands_`, and keep copy and move deleted.
   Guaranteed elision makes return-by-value, `std::deque` and `optional::emplace`
   safe ([`OwnershipCases.cpp`](../tests/review/commands/OwnershipCases.cpp)). A
   local `constexpr` table with metadata will not compile; declare it
   `static constexpr`.
2. **Check order differs between commands and fields.** Commands: argument count,
   then null pointer, then empty slot (Unavailable), then conversion and limits
   ([`TelemetryCommandBinding.h:259-304`](../lib/telemetry/detail/TelemetryCommandBinding.h#L259-L304)).
   Fields convert first and only then report an empty slot.
3. **Reserved rows** accept any argument count on the typed and runtime paths and
   return Unavailable. Their JSON and CRC are identical to those of a zero-argument
   command named "".
4. **Enum validation checks only the interval between the extreme codes.** An
   enumerator left out of an `enumSpec` subset but inside its extremes still
   executes. Enum parameters bounded with `limits()` still publish the full
   dictionary alongside the narrower min/max.
5. **Native calls accept any numeric or enum input**, including a different enum
   type ([`tests/TelemetryCommandCheck.cpp:213`](../tests/TelemetryCommandCheck.cpp#L213)).
   Only metadata values must match the signature type exactly.
6. **`forEachParameter` must emit parameters in dense signature order.** The JSON
   comma logic ([`TelemetryCommandJson.cpp:168`](../lib/telemetry/serialization/TelemetryCommandJson.cpp#L168))
   and the resource layer ([`lib/resource/telemetry/CommandsFile.cpp:62`](../lib/resource/telemetry/CommandsFile.cpp#L62))
   both depend on it.
7. **`CommandParamOps` is one shared object per (Traits, Metadata) type**, and it
   casts `metadata` back to that type. A metadata pointer and its ops must come from
   the same binding.
8. **Some schema types differ by platform.** A plain `char` infers S8 on the host
   and U8 on ARM. An unscoped enum without a fixed type is 32-bit on the host and 1
   byte on arm-none-eabi (short enums), which covers the test suite's `Legacy` enum
   ([`PlainCharParameter.cpp`](../tests/review/commands/PlainCharParameter.cpp),
   [`ArmShortEnums.cpp`](../tests/review/commands/ArmShortEnums.cpp)).
9. **Every descriptor goes through `make()` then `validateMetadata()`.** Invalid
   metadata is a compile error in constexpr tables and an `abort()` during
   construction otherwise.
10. **Only template positions are range-checked before narrowing**; runtime
    positions and IDs narrow implicitly (CM-F2).

#### What a future developer must know

1. **Presence is checked only in the adapters:**
   [`TelemetryFieldBinding.h:157`](../lib/telemetry/detail/TelemetryFieldBinding.h#L157),
   [`191`](../lib/telemetry/detail/TelemetryFieldBinding.h#L191);
   [`TelemetryFieldFactory.h:50-51`](../lib/telemetry/field/TelemetryFieldFactory.h#L50-L51),
   [`59-62`](../lib/telemetry/field/TelemetryFieldFactory.h#L59-L62),
   [`97-98`](../lib/telemetry/field/TelemetryFieldFactory.h#L97-L98),
   [`105-108`](../lib/telemetry/field/TelemetryFieldFactory.h#L105-L108);
   [`TelemetryCommandBinding.h:262-265`](../lib/telemetry/detail/TelemetryCommandBinding.h#L262-L265),
   [`289-292`](../lib/telemetry/detail/TelemetryCommandBinding.h#L289-L292),
   [`340-343`](../lib/telemetry/detail/TelemetryCommandBinding.h#L340-L343),
   [`366-369`](../lib/telemetry/detail/TelemetryCommandBinding.h#L366-L369).
   `slot.invoke()` itself is unchecked: delegate kinds trap (`call_or` plus
   `tiny::detail::trap`, independent of NDEBUG), and Function/Context kinds call
   null. A new access route must resolve once, test, and invoke that same result.
2. **Snapshot versus view.** OwnerSlot, FunctionSlot and ContextFunctionSlot `get()`
   return values. DelegateRefSlot and DelegateSlot `get()` return a view that
   re-reads the slot.
   - At -Os on ARM the invoker is loaded twice: once in the adapter, then again in
     an out-of-line `call_or` that ends in `udf #255`.
   - At -O2 the invoker and the context are loaded separately.
3. **Concurrency.** The documented contract (external serialization) is honest; the
   failure modes differ by kind.
   - On a single-core M7:
     - OwnerSlot/FunctionSlot rebinding is one aligned store against one load (old
       or new target, though the language does not guarantee it);
     - ContextFunctionSlot/DelegateRefSlot are two words loaded separately, so a
       reader can pair the old function with the new context;
     - DelegateSlot `bind` destroys the old closure in place, then stores its three
       pointers in whatever order the compiler picks. One instantiation stores
       `invoke_` before `ctx_`, so a reader can call the new invoker with a null
       context. A racing reset at -Os hits the trap.
   - On a multi-core host every kind is a data race.
   - Only a lock held across the whole call is safe.
4. **Rebinding and self-replacement.** `DelegateSlot::bind` first builds a temporary
   copy of the callable ([`TelemetryDelegateSlot.h:72`](../lib/telemetry/slot/TelemetryDelegateSlot.h#L72)).
   That copy is what makes `bind(slot.invoke())` safe; tiny's own self-alias check
   never fires for slots. Replacing a DelegateSlot from inside its own callback is
   UB, and it is silent under ASan/UBSan
   ([`OwnedSelfReplace.cpp`](../tests/review/slots/OwnedSelfReplace.cpp)).
5. **The "never allocates" guarantee comes from the slot's static assertions**
   ([`TelemetryDelegateSlot.h:56-68`](../lib/telemetry/slot/TelemetryDelegateSlot.h#L56-L68)),
   not from `tiny::delegate`.
6. **Delegate macros and the ABI tag.** Changing `TINY_DELEGATE_ENABLE_HEAP_FALLBACK`,
   `NDEBUG` or `TINY_DELEGATE_ASSERT` gives byte-identical ARM code for slot
   bind/read/write/reset ([`MacroOdrUnit.cpp`](../tests/review/slots/MacroOdrUnit.cpp),
   [`MacroOdrMain.cpp`](../tests/review/slots/MacroOdrMain.cpp),
   [`MacroOdrShared.h`](../tests/review/slots/MacroOdrShared.h)). The ABI tag
   ([`TelemetryAbi.h:59-112`](../lib/telemetry/abi/TelemetryAbi.h#L59-L112)) covers
   descriptor and index layouts only: no slot type and no delegate macro.
7. **The default owned capacity differs between host and firmware.** The default
   alignment is 16 on x64 and 8 on Cortex-M7, and pointers are 8 versus 4 bytes.
   - A closure capturing five references fails on x64 but fits on ARM; an
     `alignas(16)` capture does the opposite
     ([`CapacityPortability.cpp`](../tests/review/slots/CapacityPortability.cpp)).
   - A default DelegateSlot is 48 bytes on ARM and 64 on x64.
8. **A namespace-scope DelegateSlot has a startup cost.** It is the only kind with a
   non-trivial destructor, so it emits a startup routine in `.init_array` plus an
   `__aeabi_atexit` registration.
   - That is about 96 bytes of code; the registration does nothing because
     newlib-nano only weakly references `__register_exitproc`.
   - The shipped codegen probes cannot see this, because their slots are `extern`
     ([`SlotStartupArm.cpp`](../tests/review/slots/SlotStartupArm.cpp),
     [`SlotStartupMain.cpp`](../tests/review/slots/SlotStartupMain.cpp)).
   - The slot is still constant-initialized and the routine never writes it, so
     binding before C++ static initialization is safe.
   - All five kinds can be `constinit` in C++20 ([`ConstinitSlots.cpp`](../tests/review/slots/ConstinitSlots.cpp)).
9. **Narrowing protection.** `slotSignatureMatches` is the only narrowing guard for
   the delegate kinds; Function/Context kinds rely on exact function-pointer types.
   It is conservative except for SL-F2.
10. **Schema never depends on bind state.** JSON schema/CRC and
    [`lib/resource/telemetry/detail/Metadata.hpp:178`](../lib/resource/telemetry/detail/Metadata.hpp#L178)
    use descriptor presence only. [`ValuesFile.cpp:19-23`](../lib/resource/telemetry/ValuesFile.cpp#L19-L23)
    reports empty slots with an Unavailable status. Keep getter calls out of schema
    paths.

#### RS-F1 — LIST discards a whole page when a later entry is too long

- **Severity:** Low. **Confidence:** confirmed by repro.

#### RS-F2 — READ takes counts from a different source than construction and the fingerprint

- **Severity:** Low (latent). **Confidence:** confirmed by repro.
- **Location:** [`SchemaFile.cpp:223`](../lib/resource/telemetry/SchemaFile.cpp#L223),
  [`CommandsFile.cpp:208`](../lib/resource/telemetry/CommandsFile.cpp#L208) and
  [`:230`](../lib/resource/telemetry/CommandsFile.cpp#L230),
  [`Metadata.hpp:206`](../lib/resource/telemetry/detail/Metadata.hpp#L206), compared
  with construction at [`SchemaFile.cpp:71-97`](../lib/resource/telemetry/SchemaFile.cpp#L71-L97)
  and [`CommandsFile.cpp:56-110`](../lib/resource/telemetry/CommandsFile.cpp#L56-L110).
- **Defect:** READ writes counts taken from the ops tables (`enumCount()`,
  `parameterCount()`) and sets the Reserved flag from `invoke == nullptr` alone.
  Construction and the fingerprint use the entries actually visited. Nothing checks
  that the two agree, so a descriptor that breaks the factory invariants is served
  as Ok bytes that contradict the fingerprint and that the reference decoder rejects.
- **Scenario (a):** an `enumType<E>` specialization with `EnumOps{2,…}` whose
  traversal emits one entry. The Field record says enumCount=2, one enum record
  follows, and the header and hash say 1. The decoder rejects it as "incomplete
  schema".
- **Scenario (b):** a Command with no invoker but a parameter table. It is served
  with commandFlags=1 and parameterCount=1, which
  [`telemetryBinary.js:185`](../web/telemetryBinary.js#L185) rejects.
- Both scenarios use the specialization techniques the suite itself uses
  ([`LocalityCheck.cpp:42-63`](../tests/resources/LocalityCheck.cpp#L42-L63),
  [`MetadataSizeCheck.cpp:13-38`](../tests/resources/MetadataSizeCheck.cpp#L13-L38)).
  The library's own factories cannot produce them.
- **Repros:** [`CountSourceRepro.cpp`](../tests/review/resource/CountSourceRepro.cpp),
  [`ReservedWithParamsRepro.cpp`](../tests/review/resource/ReservedWithParamsRepro.cpp).
- **Fix idea:** at construction, require the visited count to equal `enumCount()` /
  `parameterCount()`, and `invoke != nullptr || !hasDescription()`; otherwise make
  the file size 0.

#### What a future developer must know

1. **Two size paths.** Construction runs the encoders (`MetadataMeasure`) and hashes
   those bytes. READ skips records using arithmetic sizes (`Metadata.hpp`
   `*PayloadSize`). Change the encoder, its size function and MetadataSizeCheck
   together. At READ a mismatch is caught only when the output does not end exactly
   on the record boundary ([`BlockStream.hpp:128-129`](../lib/resource/telemetry/detail/BlockStream.hpp#L128-L129)),
   and skipped records ([`:115`](../lib/resource/telemetry/detail/BlockStream.hpp#L115))
   are never checked.
2. **Count sources differ (RS-F2).** They agree only because
   `IndexedEnum::ops.count == sizeof...(Values)` and `parameterOps.count == arity`.
3. **Cursor layout.** Cursor = `kind<<62 | key<<30 | offset`; EOF = `3<<62`. A values
   Entry must have offset 0; the values Prefix accepts offsets 0..20. Each metadata
   block (the prefix plus flags, one catalog record, or one field/command with its
   children) must be at most 2^30−1 bytes. Moving records between blocks changes what
   old cursors mean.
4. **Hash domain.** Magic + major + minor + records in postorder as
   `[type, 1, 0, payload, u32 size]`. Bumping `binaryMinor` changes every
   fingerprint and the goldens (`Golden.hpp`, DecoderCheck). The JS decoder accepts
   exactly 2.1 ([`telemetryBinary.js:95-96`](../web/telemetryBinary.js#L95-L96),
   [`224-225`](../web/telemetryBinary.js#L224-L225)), so format changes must ship in
   lockstep with it.
5. **`ValuesFile(const SchemaFile&)` copies private fields**
   ([`ValuesFile.cpp:33-37`](../lib/resource/telemetry/ValuesFile.cpp#L33-L37)). A
   failed SchemaFile leaves `fields_`/`enums_` partly counted; only `size_ == 0`
   blocks reads. The values file skips empty catalogs, while the metadata files emit
   every catalog.
6. **Values width.** Each value token is `1 + payloadSize(readType)` bytes, which
   relies on `Field::read` normalizing to readType
   ([`TelemetryField.h:93-97`](../lib/telemetry/field/TelemetryField.h#L93-L97)).
   The getter runs only after the whole token has been reserved.
7. **Host and firmware can disagree** ([`PlatformTypes.cpp`](../tests/review/resource/PlatformTypes.cpp)).
   `char` is S8 on x86 but U8 on ARM; `long` is S64 on Linux but S32 on
   Windows/ARM; `wchar_t` is S32/U16/U32 on Linux/Windows/ARM; char-based enums
   follow `char`. The same catalog source then gives different schemas and
   fingerprints on host and firmware, so use fixed-width types.
8. **The heap and multiply claims are enforced only** by `run.py`'s symbol regex on
   the ARM adapter and protocol objects ([`run.py:75-80`](../tests/resources/run.py#L75-L80)).
   `ValuesFile.o` legitimately needs the float↔int64 conversion helpers
   (`__aeabi_{f,d}2{u,}lz`, `__aeabi_{u,}l2{f,d}`).
9. **Protocol envelope sizes are hard-coded** as 12/6/14 bytes
   ([`Protocol.cpp:17-19`](../lib/resource/protocol/Protocol.cpp#L17-L19)) and must
   match both READMEs. LIST never calls `size()`; STAT does.
10. **Keep the `CurrentAbiTag` default arguments** on the three index constructors;
    they are what makes mixed layouts fail at link time (`AbiCheck.cpp`).

  only `tests/run_checks.py` at C++17 with MinGW 13.1 (section 2). Not run:
  `tests/run_checks.py` at C++20, the sanitized full run, `tests/run_arm_checks.py`,
  `tests/resources/run.py` (host, sanitized and ARM), the qmake `no_json` target.
  The Qt playground was built and smoke-tested once by the coordinator only.
- **JavaScript:** `tests/resources/DecoderCheck.mjs` was not run anywhere (no Node);
  the decoder was reviewed by reading and cross-checked with a Python decoder.
- **Locales:** glibc multibyte decimal separators (WSL has no such locale); the
  runtime output of newlib-nano `%g` (linked, not executed).
- **Code areas outside a slice's ownership:** command-argument conversion was left to
  the commands slice; JSON writer internals were not reviewed by the commands slice;
  tiny_delegate features the slots do not use (`delegate_sbo`, heap mode,
  `bind_context`, delegate move); enum reflection beyond its JSON use; the compile
  cost of 65536-row tables; the owner's `size_attribution.py` / `os-attribution.json`
  beyond reconciling their total.
- **Pending:** the fields slice (5.2) and the critic (section 6).
